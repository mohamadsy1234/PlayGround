# Plan: Production-Ready Digital Twin Extension

## Objective
Make the Chrome extension fully functional, wired with real data, and ready for actual use on `web.whatsapp.com`.

---

## Current State (Verified)
- ✅ Manifest V3, content-script, background, all lib modules load
- ✅ Core automation works: state machine (10 states), language detection, intent extraction, humanizer, rate limits, typing simulation
- ✅ UI exists: popup, options, dashboard (HTML/CSS)
- ⚠️ Icons are tiny placeholders (126-642 bytes)
- ⚠️ Dashboard shows dummy data (`Math.random()`)
- ⚠️ Popup stats never update (content-script doesn't write `rateLimiterStats`)
- ⚠️ Options pricing/templates saved but **not used** by nucleus/wa-adapter
- ❌ Voice notes, media, OCR, CRM, A/B, Ghost Mode — marked as future phases (out of scope for this plan)

---

## Required Changes

### 1. Build Proper Branded Icons
**Files:** `digital-twin-extension/icons/icon-16.png`, `icon-48.png`, `icon-128.png`
- Create emerald/green robot-themed icons matching dashboard brand (`from-emerald-500 via-teal-400 to-cyan-500`)
- Use SVG source → export PNG at 16×16, 48×48, 128×128
- Verify: `file icons/*.png` shows correct dimensions, Chrome loads without warning

### 2. Wire Dashboard to Real IndexedDB Data
**File:** `digital-twin-extension/dashboard/dashboard.js`
- Import `storage.js` (DigitalTwinStorage) in dashboard context
- Replace `Math.random()` with actual queries:
  - `getAllSessions()` → total customers, active conversations
  - `getEventsByType('conversion')` → conversions today
  - Sum session `totalPaid` → estimated revenue
  - Group sessions by `country` → country breakdown
  - Build funnel from state transitions in events
  - Recent sessions table from `getAllSessions()` sorted by `updatedAt`
- Add 5s auto-refresh (already has `setInterval`)

### 3. Fix Popup Stats Sync
**Files:** `digital-twin-extension/content-script.js`, `digital-twin-extension/popup/popup.js`
- In content-script: after `humanizer.checkLimits()` or on each auto-reply, write current stats to `chrome.storage.local.set({ rateLimiterStats: { sentThisHour, sentLast10Min, consecutiveAutoReplies } })`
- In popup.js: the existing poll will then read real data

### 4. Make Options Pricing & Templates Usable
**Files:** `digital-twin-extension/lib/nucleus.js`, `digital-twin-extension/options/options.js`, `digital-twin-extension/content-script.js`
- **Pricing:** Move pricing config from hardcoded in `nucleus.js` to `chrome.storage.local` (key: `pricingConfig`). Load in nucleus `init()`. Options page reads/writes same key.
- **Templates:** Options saves `template1`, `template2` to storage. Content-script `INSERT_TEMPLATE` command should read from storage and insert via `wa-adapter.sendText()`.
- Remove hardcoded pricing array from `nucleus.js` constructor; use loaded config.

### 5. End-to-End Verification
**Steps:**
1. Load unpacked extension in Chrome (`chrome://extensions/` → Developer mode → Load unpacked → select `digital-twin-extension/`)
2. Open `web.whatsapp.com`, log in
3. Verify floating button appears bottom-right ("الأتمتة موقوفة")
4. Toggle ON (`Ctrl+Shift+A`) → "الأتمتة تعمل" + green pulse
5. Receive test message in open chat → verify auto-reply fires after human delay (2-8s) with typing indicator
6. Open popup → verify stats increment
7. Open dashboard (`Ctrl+Shift+D`) → verify real KPIs, funnel, country data
8. Open options → change pricing/template → verify used in next auto-reply
9. Test rate limiting: send >12 msgs in 10min → auto pauses
10. Test working hours: outside 8am-2am → auto pauses
